# Scripts

Development and build tooling scripts.

- `check-no-committed-env.sh` — CI guard; rejects a committed `.env` and scans every `.env.example` against a fixed prefix list (AWS/GitHub/Slack/Stripe-shaped keys, a JWT, a PEM private-key header, credentials embedded in a URL). That is a fast, dependency-free tripwire for those specific shapes — not a general "is this a real credential" scanner, and it will not catch an ordinary password. Run via `pnpm check:env`.
- `dev-reset.sh` — wipes and recreates the shared Docker Compose development stack (`infra/docker-compose.yml`). See `docs/deployment-development.md` "Database lifecycle". Committed with the executable bit set (`chmod +x`, required on the Ubuntu host); also runnable as `pnpm dev:reset` from any checkout, including Windows, where the executable bit doesn't survive a clone.
- `admin-config.mjs` — reads and changes admin-managed configuration (validation thresholds, value sets, clinical default ranges) without editing a migration. This is the maintenance script ADR-0008 sequences between P3 and P8, and R7 is what made it overdue: a threshold could previously only be changed by writing a new migration, which is a release, while AC 13.2 AC2 wants the change to govern from the next client fetch. Also `pnpm admin:config`. Three things in it are load-bearing rather than incidental. It speaks **HTTP to the admin API, never SQL to the database**: every one of these writes is audited with the actor and before/after values inside the write's own transaction, and a `psql` UPDATE produces no audit row at all — leaving a log that records a bound changed with no record of what it used to be, which nothing else can reconstruct. It refuses a token with no `sub` **before** making the request, because `grant_type=client_credentials` mints exactly that and `sub` is what the audit row records as the actor — the API answers a bare `401 ADMIN_AUTH_MISSING_SUBJECT_CLAIM`, which reads as a broken guard. And it derives the development token endpoint from `ADMIN_OIDC_ISSUER` rather than from the API URL, because the mock IdP bakes the request's Host header into `iss` and the API compares it by exact string equality — the same trap `android-emulator.sh` documents for the patient issuer. It will not mint a token at all against a stack that does not report itself as development; set `ADMIN_TOKEN` for that. `--help` lists the commands and the environment.
- `android-emulator.sh` — manages a Pixel 8 AVD for testing `apps/mobile` on-device (`doctor | create | start | wire | up | status | logcat | fingerprint | stop | wipe`). Also exposed as `pnpm --filter @ostomy/mobile emulator:*`. Three things in it are load-bearing rather than incidental: it forwards host ports with **`adb reverse`, never `10.0.2.2`**, because `mock-oidc` advertises an `issuer` derived from the request's Host header and the API validates `iss` against `http://localhost:8090/patient-issuer` — reaching the IdP by any other name yields tokens that are rejected after a sign-in that looked fine; it forwards **only** the api and mock-oidc ports, because a patient device has no business reaching MinIO's console or the admin SPA; and `doctor` reports what is missing without installing anything, since every missing piece is a multi-hundred-megabyte SDK download. On Windows it must run under **Git Bash**: from PowerShell or cmd the bare word `bash` resolves to WSL's `C:\Windows\System32\bash.exe`, which cannot reach the Windows SDK or adb server — the script detects that case and explains it rather than failing obscurely. `.claude/skills/android-emulator/SKILL.md` carries the judgement around it, including what an emulator run does and does not prove, and the three things that bite on a first development build (JDK 17-21 — not Android Studio's bundled 25; `--device` takes the AVD name, not the adb serial; and a `Read timed out` from dl.google.com just needs a re-run).
