# Scripts

Development and build tooling scripts.

- `check-no-committed-env.sh` — CI guard; rejects a committed `.env` and scans every `.env.example` against a fixed prefix list (AWS/GitHub/Slack/Stripe-shaped keys, a JWT, a PEM private-key header, credentials embedded in a URL). That is a fast, dependency-free tripwire for those specific shapes — not a general "is this a real credential" scanner, and it will not catch an ordinary password. Run via `pnpm check:env`.
- `dev-reset.sh` — wipes and recreates the shared Docker Compose development stack (`infra/docker-compose.yml`). See `docs/deployment-development.md` "Database lifecycle". Committed with the executable bit set (`chmod +x`, required on the Ubuntu host); also runnable as `pnpm dev:reset` from any checkout, including Windows, where the executable bit doesn't survive a clone.
- `admin-config.mjs` — reads admin-managed configuration (validation thresholds, value sets, clinical default ranges) and changes a **threshold**, without editing a migration. This is the maintenance script ADR-0008 sequences between P3 and P8, and R7 is what made it overdue: a threshold could previously only be changed by writing a new migration, which is a release, while AC 13.2 AC2 wants the change to govern from the next client fetch. Also `pnpm admin:config`; `--help` lists the commands and the environment. **`list` reads all three surfaces, `set-threshold` is the only write** — the value-set and default-range endpoints exist (P3.S3 PRs A and C) and have no command here, so those two stay migration-only until the console, including the heart-rate red flag that #94 moved into `clinical_default_ranges`. The default-range listing shows withdrawn rows in their own group since #98, marked restorable, for the same reason the value-set listing marks retired members: an admin needs to see what was taken out. There is no `restore` command — recovering a row is a `POST /admin/default-ranges/{id}/restore` away and still waits on the console.

  Four things in it are load-bearing rather than incidental.

  It speaks **HTTP to the admin API, never SQL to the database**: every one of these writes is audited with the actor and before/after values inside the write's own transaction, and a `psql` UPDATE writes no audit row at all — leaving the row's own `updated_at` as the only trace of a change that nothing else can reconstruct, since no stored observation records which bound checked it. ADR-0008 said "a script against the database" until this existed; it is amended.

  There is **deliberately no `localhost` default for the issuer**. The mock IdP bakes the request's Host header into the token's `iss` and the API compares it by exact string equality, so `ADMIN_OIDC_ISSUER` falls back to `http://$DEV_HOST_ADDRESS:8090/admin-issuer` — read from the environment or from `.env`, as Compose reads it — and **minting refuses rather than guess**. The first version did default to `localhost`, which is the one default `.env.example` spends twenty lines refusing to provide, and against a correctly configured stack it made every request fail `401 ADMIN_AUTH_INVALID_ISSUER`. Related trap worth knowing: if `DEV_BIND_ADDRESS` is left at `127.0.0.1` while `DEV_HOST_ADDRESS` is a LAN address, mock-oidc is only reachable at `localhost:8090` and there is no address at which minting can produce an acceptable token — set `ADMIN_TOKEN`, or bind wider. `android-emulator.sh` documents the same trap for the patient issuer.

  It refuses a token with no subject claim **before** making the request, because `grant_type=client_credentials` mints exactly that and the subject is what the audit row records as the actor — the API otherwise answers a bare `401 ADMIN_AUTH_MISSING_SUBJECT_CLAIM`, which reads as a broken guard. The claim name is configuration (`ADMIN_OIDC_SUBJECT_CLAIM`), so it is read rather than assumed.

  And it will not mint a token against a stack that does not report a build commit. That is a **guard against a mistyped command, not a security boundary** — `nodeEnv` defaults to `development` when unset, and a real dev stack built without `BUILD_COMMIT` reports none either — so set `ADMIN_TOKEN` for anything that is not the local Compose stack. Exit codes: `0` done, `1` refused, `2` unreachable, `3` the script itself failed.
- `android-emulator.sh` — manages a Pixel 8 AVD for testing `apps/mobile` on-device (`doctor | create | start | wire | up | status | logcat | fingerprint | stop | wipe`). Also exposed as `pnpm --filter @ostomy/mobile emulator:*`. Three things in it are load-bearing rather than incidental: it forwards host ports with **`adb reverse`, never `10.0.2.2`**, because `mock-oidc` advertises an `issuer` derived from the request's Host header and the API validates `iss` against `http://localhost:8090/patient-issuer` — reaching the IdP by any other name yields tokens that are rejected after a sign-in that looked fine; it forwards **only** the api and mock-oidc ports, because a patient device has no business reaching MinIO's console or the admin SPA; and `doctor` reports what is missing without installing anything, since every missing piece is a multi-hundred-megabyte SDK download. On Windows it must run under **Git Bash**: from PowerShell or cmd the bare word `bash` resolves to WSL's `C:\Windows\System32\bash.exe`, which cannot reach the Windows SDK or adb server — the script detects that case and explains it rather than failing obscurely. `.claude/skills/android-emulator/SKILL.md` carries the judgement around it, including what an emulator run does and does not prove, and the three things that bite on a first development build (JDK 17-21 — not Android Studio's bundled 25; `--device` takes the AVD name, not the adb serial; and a `Read timed out` from dl.google.com just needs a re-run).
